# 스타일 프로필 스키마

성공했던 페퍼톤스 Suno 프롬프트(GPT 심층리서치 도출문)를 역설계해서 만든 8개 항목.
각 프로필은 `styles/<이름>.yaml` 파일 하나.

## 항목

| 키 | 뜻 | 왜 필요한가 |
|---|---|---|
| `identity` | 한 줄 정체성 (영어) | Suno 프롬프트의 첫 문장. 전체 톤을 잡음 |
| `instrumentation` | 편성 화이트리스트 + 각 악기의 역할 | "무엇을 쓸지"보다 **"무엇을 쓰지 않을지"**가 결과를 좌우 |
| `tempo_rhythm` | BPM 범위, 리듬 느낌 | Suno가 가장 잘 따르는 지시 중 하나 |
| `harmony` | 조성 경향, 코드 성격 | "밝지만 씁쓸한" 같은 정서는 화성에서 나옴 |
| `melody_hooks` | 멜로디 성격, 훅 장치 | 기타 리프·카운터멜로디 등 귀에 걸리는 요소 |
| `dynamic_arc` | 기승전결 (시간축 전개) | 도입→전개→폭발. Suno가 구조를 잡는 근거 |
| `vocal` | 보컬 캐릭터와 딕션 | 음색·발성·표현 강도 |
| `production` | 믹스/공간감/질감 | 같은 편성도 프로덕션으로 완전히 달라짐 |
| `constraints` | 금지 조항 (부정 지시) | 성공 사례에서 결정적이었던 부분 |
| `grounding` | 근거가 된 실제 좋아요 곡 | 프로필이 감이 아니라 데이터에 기반함을 보증 |

### 선택 항목

| 키 | 뜻 |
|---|---|
| `structure` | 섹션별 구조 지시. Suno의 **가사 칸**에 들어갈 `[Intro]` `[Verse]` 태그를 만든다. 없으면 편성에서 기본 골격을 자동 생성 |

```yaml
structure:
  - section: Intro
    note: clean electric guitar harmonics, two bars, no drums
  - section: Verse 1
    note: acoustic guitar and vocal only
```

## 작성 원칙

1. **형용사 대신 메커니즘.** "청량하다"(X) → "jangly한 클린 기타가 보컬 사이사이를 채운다"(O)
2. **화이트리스트로 쓴다.** 편성은 "이것만" 형태로. 나열하지 않은 악기는 안 나오는 게 목적.
3. **시간축을 명시한다.** "점점 고조된다"(X) → "2마디 하모닉스 → 어쿠스틱 단독 도입 → 풀밴드 코러스"(O)
4. **금지 조항을 반드시 넣는다.** Suno는 지시하지 않으면 자기 습관대로 간다.
5. **숫자는 실측으로 바꾼다.** BPM 같은 수치는 AI가 쓰면 추측이다.
   `measure_audio.py` 로 재고 `check_profile_numbers.py` 로 대조할 것.
6. **사용자 귀로 교정한다.** AI 초안은 출발점일 뿐. 생성 결과를 듣고 고친 버전이 진짜 자산.
